# Changes to Aimiru for Claude Code

## 0.3.0-rc.5 (pre-release, 11 Nov 2026)

- Claude Code's own housekeeping no longer asks you. Steps that only keep its own books (its task list, plans, questions to you, loading a skill, searching for tools, handing back an answer) and reads of your own computer go ahead without a question or a card in Aimiru. Still asked about: writing a file outside your project, changing Claude Code's or Aimiru's settings, a git guard, pushing, sending, paying, publishing a page to claude.ai, running a program Claude Code wrote that is new, and any step Aimiru does not recognise. Changes inside your project go ahead, as before.
- Reading with a few chained commands (`cd`, `;`, `&&`, `|`, `head`, `echo`) is a read when every part reads: `git status`, `git log`, `git diff`, `git show`, `git rev-parse`, `git worktree list`, `git branch`, `ls`, `cat`, `pwd`, `uptime`, `ps`. `git fetch` and `git ls-remote` still ask, once.
- What a step writes is judged by where it really lands. A link inside your project that leads to Claude Code's or Aimiru's settings counts as those settings. A new git guard (a file in `.git/hooks`, or in the folder `core.hooksPath` names, called `pre-commit`, `pre-push` or another name git runs) and any mode change on one ask, as changing an existing one does. Files saved by `git ... --output`, `git archive -o`, `git format-patch -o`, `git checkout-index --prefix` and `git worktree add` are judged by the folder they land in, and a git step whose landing Aimiru cannot read with certainty asks. Saving a page from claude.ai into a folder is judged by that folder; publishing one asks the first time you publish to claude.ai. Capital letters in a settings path no longer hide it (`~/.CLAUDE`).
- Identical steps wait on one question. When Claude Code runs the same step more than once at the same time, you are asked once, and the answer you give reaches the others. Steps that differ in the folder they run in, in a helper they run from, or in running outside Claude Code's sandbox are their own questions.
- Ask why reaches Claude Code (ADR-0201). When you tap Ask why on one of Claude Code's asks, Claude Code reads your question the next time it tries that step, and answers you once with Aimiru's `answer_why` tool, in a sentence or two. Its answer shows on the ask under your answers, as Claude Code's own words, with Aimiru's note that it has not checked them. It changes nothing about the ask: the step still waits for your yes or no. Aimiru says Claude Code will hear your question only from version 0.3.0-rc.5.
- Your yes finishes the job (ADR-0172). A job the runner started whose step Aimiru asks you about will no longer end without it: the job stays open with "Waiting for your answer", and once you have answered, the runner has Claude Code go on with that same job once. The step you said yes to runs exactly as you were asked about it; a no, an ended question, a yes that came after its question ended, or a changed step does not run. With no yes it can use, a job you closed, or questions that ended more than an hour ago, the job ends without going on. Nothing goes on while you have paused.
- Subagents get your brief. A subagent Claude starts with its Agent tool begins without the session's context, so it never had your brief. Now the plugin gives each one your brief as it starts, before its first prompt, exactly as Aimiru wrote it and nothing else (no job, none of Aimiru's other words). It asks Aimiru for at most 2 seconds; with no answer, no brief, a brief that is switched off for Claude Code, or a Pause, the subagent starts as before and nothing is shown. A brief over Claude Code's 10,000 characters is left out whole. The doctor says when the last subagent got your brief. The plugin keeps only that time and the outcome, never your words.
- What to do: `claude plugin marketplace update aimiru`, then `claude plugin update aimiru@aimiru`, and restart Claude Code. If the runner was on, run `node "<plugin>/scripts/runner.mjs" on` again.

## 0.3.0-rc.4 (pre-release, 3 Nov 2026)

- Each read Aimiru allows on your computer inside a job you gave Claude Code now names that job in Aimiru, as every other checked step already did, so the job's record holds every step and Aimiru's closing check reads them all. Nothing about how a step is decided changes.
- The runner's `on` waits for the runner that was already on to stop, tries the start again, and says plainly when it did not start.
- What to do: `claude plugin marketplace update aimiru`, then `claude plugin update aimiru@aimiru`, and restart Claude Code. If the runner was on, run `node "<plugin>/scripts/runner.mjs" on` again.

## 0.3.0-rc.3 (pre-release, 30 Oct 2026)

- Aimiru's files now live in `~/.aimiru` when Claude Code gives the plugin no folder of its own, and the runner's copy is in `~/.aimiru/runner`. Settings are named `AIMIRU_...` (`AIMIRU_AGENT_TOKEN`, `AIMIRU_BASE_URL`, `AIMIRU_TAKE_TASKS` and the rest), and the address setting under `/plugin configure` is now `aimiru_url`. What to do: run the install lines again, or `claude plugin marketplace update aimiru` then `claude plugin update aimiru@aimiru`, and restart Claude Code. The key `/aimiru:connect` saved stays where it was and keeps working; an address you typed under `/plugin configure`, type again. If the runner was on, run `node "<plugin>/scripts/runner.mjs" on` again.
- Aimiru's own tools are now named `mcp__plugin_aimiru_aimiru__<tool>`, and the routine is the skill `aimiru:aimiru`. A rule of yours that names one of Aimiru's tools by its full name, write again with the new name.
- Keys Aimiru gives from now on start `aimiru_agt_`.

## 0.3.0-rc.2 (pre-release, 29 Oct 2026)

- Your brief: each session gets what you told Aimiru about yourself as it starts, right after Aimiru's own words and exactly as Aimiru wrote it. If you change it while a session is open, Claude Code gets the new one with your next message. If Aimiru could not answer in time as the session started, Claude Code asks for your brief again with your first message, once; if that fails too, a later message brings it, as before. The plugin keeps only which version a session was given, never your words.
- Jobs you give Claude Code in Aimiru: the next session you start in your terminal takes the job, and you read one line saying so; Claude starts it at your first message. After `/clear`, Claude gets the same job again with your next message while Claude Code keeps the same session. Scripted runs (`claude -p`, the SDK) never take one. `AIMIRU_TAKE_TASKS=0` turns this off on a computer.
- While a session works on your job, each of its checks names the job, so Aimiru can show you each step with it.
- The doctor says whether this computer takes your jobs, and when Aimiru last gave Claude Code your brief.
- The runner: `node "<plugin>/scripts/runner.mjs" on` starts each job you give Claude Code within seconds of your send, with `claude -p` in the folder you chose, under Aimiru's check (Claude Code must say it loaded the check before its first step, or the job stops), with no session open; `off` and `status` on the computer, Turn off on Today (ADR-0161).
- `/aimiru:import` brings what Claude Code already knows about you into Aimiru: it reads your own `CLAUDE.md`, this project's and Claude Code's notes on this project, on this computer, shows the facts about you it found, and sends only the ones you keep. `/aimiru:connect` asks about it once.
- The runner takes email addresses and phone numbers out of its short notes on a job and out of what Claude Code says when the job ends, on this computer, before either is sent to Aimiru or kept to send later. Each becomes `[email]` or `[phone]`. Card numbers and keys are taken out as before, and Aimiru's check of each step is unchanged.

Earlier changes are in the history of `aimiru-app/aimiru-connectors`.
